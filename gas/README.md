# Apps Script — API «Бюджета»

## Установка

1. Открыть таблицу → **Расширения → Apps Script**.
2. Заменить содержимое `Код.gs` содержимым [Code.gs](Code.gs).
3. **Настройки проекта** (шестерёнка слева) → включить «Показывать файл манифеста appsscript.json» →
   открыть `appsscript.json` в редакторе и заменить содержимым [appsscript.json](appsscript.json).
4. Проверить часовой пояс таблицы: **Файл → Настройки → Часовой пояс** — `(GMT+05:00) Алматы`.
   Он должен совпадать с `timeZone` в манифесте, иначе даты будут съезжать на день.
5. В редакторе выбрать функцию `debugSnapshot` → **Выполнить** → выдать доступ
   («Дополнительные настройки → Перейти на страницу…» — это нормально для своего скрипта).
   В журнале должен появиться JSON со сводкой.
6. Выбрать `debugWriteCycle` → **Выполнить**. В журнале: добавление, `duplicate: true`, изменение, удаление.
   В таблице после этого ничего лишнего не остаётся.
7. **Начать развёртывание → Новое развёртывание** → тип «Веб-приложение»:
   - Запуск от имени: **Я**
   - У кого есть доступ: **Все**
8. Скопировать URL вида `https://script.google.com/macros/s/…/exec` — его вводим в приложении
   при первом запуске. В репозиторий URL не кладём.

## Обновление кода

После правок: **Начать развёртывание → Управление развёртываниями → ✏️ → Версия: новая версия**.
Так URL остаётся прежним. «Новое развёртывание» создаёт новый URL — телефоны придётся перенастраивать.

## Протокол

`GET <url>` → текущее состояние:

```json
{
  "ok": true,
  "summary": { "todayLeft": 1137, "dailyLimit": 1137, "freeNow": 38659, "balanceNow": 19446, "daysLeft": 34, "...": "все ключи из колонки C «Свода»" },
  "top": [{ "category": "Такси", "count": 12 }],
  "categories": [{ "name": "Продукты", "type": "Расход" }],
  "accounts": ["Kaspi Егор", "..."],
  "who": ["Егор", "Арина"],
  "expected": [{ "id": "p0012", "date": "2026-10-12", "amount": 140000, "left": 137000, "category": "Поесть", "type": "Расход", "overdue": false }],
  "recent": [{ "id": "…", "date": "2026-09-28", "amount": 5000, "category": "Продукты", "account": "Kaspi Егор", "who": "Егор", "comment": "" }],
  "serverTime": "2026-09-28T04:00:00.000Z"
}
```

`POST <url>`, тело — JSON строкой с `Content-Type: text/plain` (чтобы браузер не делал CORS-preflight):

| action | Поля | Что делает |
|---|---|---|
| `add` | `tx: { id, date: "ГГГГ-ММ-ДД", status, type, amount, category, account, who, comment }` | `appendRow`. Если `id` уже есть — ничего не пишет, `result.duplicate = true`. Неизвестная категория дописывается в «Справочники» |
| `update` | `id`, `fields: { …любые поля tx }` | Правит строку, найденную по ID |
| `delete` | `id` | Удаляет строку, найденную по ID |

Ответ на POST — то же, что GET, плюс `result`. Ошибка — `{ "ok": false, "error": "текст" }`.

Все записи идут под `LockService`, строки ищутся по ID, а не по номеру — одновременная работа
с двух телефонов строки не портит.

## Что считает таблица, а что скрипт

- Все цифры (остаток, лимит, план-факт, топ-5) — формулы «Свода». Скрипт читает их по ключам
  из колонки C, поэтому строки «Свода» можно переставлять и добавлять новые ключи.
- Скрипт только отбирает строки для списков: «Ожидаемые» (план, не закрытый фактом, до +14 дней,
  включая просроченные) и «Последние операции» (20 последних записей со статусом «Факт»).
