# Apps Script — API «Бюджета»

## Установка

1. Открыть таблицу → **Расширения → Apps Script**.
2. Заменить содержимое `Код.gs` содержимым [Code.gs](Code.gs).
3. **Настройки проекта** (шестерёнка слева) → включить «Показывать файл манифеста appsscript.json» →
   открыть `appsscript.json` в редакторе и заменить содержимым [appsscript.json](appsscript.json).
4. Проверить часовой пояс таблицы: **Файл → Настройки → Часовой пояс** — `(GMT+05:00) Алматы`.
   Он должен совпадать с `timeZone` в манифесте, иначе даты будут съезжать на день.
5. В редакторе выбрать функцию `debugSnapshot` → **Выполнить** → выдать доступ
   («Дополнительные настройки → Перейти на страницу…» — это нормально для своего скрипта).
   В журнале должен появиться JSON со сводкой.
6. Выбрать `debugWriteCycle` → **Выполнить**. В журнале: добавление, `duplicate: true`, изменение, удаление.
   В таблице после этого ничего лишнего не остаётся.
7. **Начать развёртывание → Новое развёртывание** → тип «Веб-приложение»:
   - Запуск от имени: **Я**
   - У кого есть доступ: **Все**
8. Скопировать URL вида `https://script.google.com/macros/s/…/exec` — его вводим в приложении
   при первом запуске. В репозиторий URL не кладём.

## Миграции (один раз, по порядку версий)

- `migrateAccountsV2` — колонка «На счёт» в «Транзакциях» (переводы), лист «Счета».
- `migrateAccountsV3` — сверки счетов вместо остатка на начало периода, лист «История счетов».
  Сама вызывает v2, так что на чистой таблице достаточно запустить только её.

Обе безопасны при повторном запуске.

**Как теперь считаются остатки.** На листе «Счета» у каждого счёта есть сверка: сумма (B) и момент (C).
«Сейчас» = сумма сверки + операции, записанные после неё. Сверка делается из приложения тапом по счёту
в «На счетах» — каждая пишется на лист «История счетов», записи старше 60 дней удаляются сами
(это только журнал, на остатки не влияет). «На счетах» на «Своде» = сумма по счетам; свободные деньги =
на счетах + ещё ожидаемые доходы − ещё не оплаченные плановые расходы.

## v4: прогноз, «Календарь план», период и архив

`migrateV4` — один раз (повторно безопасно):
- «Справочники»: колонка C «Обязательная» (рассрочки, учёба, коммуналка и т.п. — по ним прогноз не считает темп);
  недостающие пары «категория + тип» (например «Прочие» как доход).
- «Свод»: категории считаются с учётом типа; колонки L «Факт за 7 дней», M «Обязательная»;
  блок прогноза: `lifeMoney`, `dailyBudget`, `pace7`, `runOutDate`, `forecastGap`, `payday`.
- Период переводится на «с 10-го по 9-е» (`PERIOD_START_DAY`), прошедшее пишется в лист «Архив».
- Комментарии, ставшие формулой (#NAME?), возвращаются текстом.

**Период сдвигается сам**: при первом запросе приложения или открытии таблицы после конца периода
итоги закрытого периода записываются в «Архив» (план, факт, отклонение по статьям), «Свод» переходит
на следующий. Транзакции не удаляются.

**«Календарь план»** — редактируемая сетка «статья × день». Правка ячейки сразу переписывает плановые строки
«Транзакций» за этот день (`onEdit`); сетка перестраивается при открытии таблицы и из меню
«Бюджет → Обновить Календарь план». Колонки: План · Потрачено · Осталось; серые зачёркнутые дни уже покрыты фактом.

## Обновление кода

После правок: **Начать развёртывание → Управление развёртываниями → ✏️ → Версия: новая версия**.
Так URL остаётся прежним. «Новое развёртывание» создаёт новый URL — телефоны придётся перенастраивать.

## Протокол

`GET <url>` → текущее состояние:

```json
{
  "ok": true,
  "summary": { "todayLeft": 1137, "dailyLimit": 1137, "freeNow": 38659, "balanceNow": 19446, "daysLeft": 34, "...": "все ключи из колонки C «Свода»" },
  "top": [{ "category": "Такси", "count": 12 }],
  "categories": [{ "name": "Продукты", "type": "Расход" }],
  "accounts": ["Kaspi Егор", "..."],
  "who": ["Егор", "Арина"],
  "expected": [{ "id": "p0012", "date": "2026-10-12", "amount": 140000, "left": 137000, "category": "Поесть", "type": "Расход", "overdue": false }],
  "recent": [{ "id": "…", "date": "2026-09-28", "amount": 5000, "category": "Продукты", "account": "Kaspi Егор", "who": "Егор", "comment": "" }],
  "serverTime": "2026-09-28T04:00:00.000Z"
}
```

`POST <url>`, тело — JSON строкой с `Content-Type: text/plain` (чтобы браузер не делал CORS-preflight):

| action | Поля | Что делает |
|---|---|---|
| `add` | `tx: { id, date: "ГГГГ-ММ-ДД", status, type, amount, category, account, toAccount, who, comment }` | `appendRow`. Если `id` уже есть — ничего не пишет, `result.duplicate = true`. Неизвестная категория дописывается в «Справочники» |
| `update` | `id`, `fields: { …любые поля tx }` | Правит строку, найденную по ID |
| `delete` | `id` | Удаляет строку, найденную по ID |
| `setBalance` | `account`, `value`, `who` | Сверка: «сейчас на счёте value». Пишет историю |

Ответ на POST — то же, что GET, плюс `result`. Ошибка — `{ "ok": false, "error": "текст" }`.

**Перевод между счетами:** `type: "Перевод"`, `account` — откуда, `toAccount` — куда. Статус всегда «Факт»,
категория «Перевод». Не считается ни расходом, ни доходом — на лимит и план-факт не влияет, только на остатки
по счетам (лист «Счета»). GET отдаёт их в `balances: [{ name, start, now }]`.

Все записи идут под `LockService`, строки ищутся по ID, а не по номеру — одновременная работа
с двух телефонов строки не портит.

## Что считает таблица, а что скрипт

- Все цифры (остаток, лимит, план-факт, топ-5) — формулы «Свода». Скрипт читает их по ключам
  из колонки C, поэтому строки «Свода» можно переставлять и добавлять новые ключи.
- Скрипт только отбирает строки для списков: «Ожидаемые» (план, не закрытый фактом, до +14 дней,
  включая просроченные) и «Последние операции» (20 последних записей со статусом «Факт»).
